# 파일 자동 구조화 Agent — Step1 테스트 기록

> 목적: Gmail 자동화 이전 단계에서 **Flowise Agent의 분류 정확도** 확인 및 프롬프트 튜닝을 위한 테스트 기록

---

## 🎯 Step1 목표 정의

**목표:**
- 첨부파일 데이터(fileName, fileContent)를 입력하면
- Flowise Agent가 **JSON만** 출력하며
- 프로젝트명, 날짜, 문서 타입(docType), 최종 폴더 구조, 태깅 정보를 생성한다.

**현재 스코프:**
- Tool 사용 없음
- Gmail Trigger 없음
- n8n 없음
- 순수 Flowise Agent inference만 검증

즉,
> “AI가 파일을 어떻게 분류할지 판단 능력을 확보하는 단계”

```
[Chat Input] → [Agent 0 (ChatOpenAI)] → [Text Output]
```

- Model: gpt-4o-mini (OpenAI)
- Temperature: 0.9
- Tools: None

## 📝 System Prompt (Agent Behavior)

**위치:**  
Agent 0 → Messages → System

```text
You are an AI system designed to classify and structure documents.
The user will input file information.

Your task:
- Analyze fileName, fileExtension, and fileContent
- Infer projectName, year, month, docType
- Decide folder path and tagging policy
- Output a JSON object ONLY (no text outside JSON)

Output Format:
{
  "projectName": "",
  "year": "",
  "month": "",
  "docType": "",
  "finalFolderPath": "",
  "newFileName": "",
  "tags": [],
  "storageType": ""
}

Definition:
- projectName: extract from fileName or content
- year/month: extract date from name or content, otherwise ""
- docType: classify one of ["회의록","계약서","견적서","인보이스","보고서","매뉴얼","기타"]
- finalFolderPath: "/{projectName}/{year}/{month}/{docType}"
- newFileName: recommended file name
- tags: ["projectName","docType",optional]
- storageType: decide "public","private", or "confidential"

Constraints:
- ONLY output JSON (no explanation)
- If unknown, use ""
- Strict JSON formatting
```

## 🧪 테스트 방법

테스트는 메일 자동화 대신 **직접 입력 방식**으로 진행했다.

이유:
- Gmail Trigger 이전에 **분류 로직 정확성** 확보 필요
- 실수 방지: 폴더 구조/파일명 자동화는 높은 정확도 필수
- 다양한 문서 케이스 테스트를 위해 수동 방식이 효과적

프로세스:
1. Flowise Preview 창에서
2. `fileName`, `fileContent`를 직접 입력
3. JSON 결과 복사
4. 성공/실패 케이스 기록
5. Prompt 개선 포인트 도출

## 📂 테스트 Input 샘플

아래 샘플을 사용하여 분류 테스트를 진행했다.

### Case A — 정상 회의록 (정보 풍부)
```
fileName: 프로젝트A_회의록_2025-09-14_v2.docx
fileContent:
2025년 9월 14일 프로젝트A 개발팀 회의록.
참석자: 홍길동(PM), 김개발(Backend), 이디자인(Web)...
```

### Case B — 프로젝트명 없음
```
fileName: 회의록_final.docx
fileContent:
2025년 1월 3일, 프로젝트X 킥오프 회의...
```

### Case C — 내용 부족
```
fileName: 프로젝트B_회의록.docx
fileContent:
프로젝트B 회의 진행.
```

### Case D — 견적서
```
fileName: 프로젝트C_견적서_2025-02.pdf
fileContent:
발주처: C사
견적 총액: 25,000,000원
...
```

### Case E — 영어 문서
```
fileName: Meeting_notes_Apollo_2024-07.docx
fileContent:
2024-07-11 Apollo project kickoff meeting...
```

### Case F — 계약서
```
fileName: 프로젝트D_계약서_final.pdf
fileContent:
프로젝트D 계약서.
계약 기간: 2025-01-01 ~ 2025-12-31
...
```

### Case G — Invoice
```
fileName: Invoice_CustomerE_2025-06.pdf
fileContent:
Invoice to: CustomerE
Amount: $12,500
Project: RenewalE
```

### Case H — 파일명 혼란 (실무 흔한 케이스)
```
fileName: 최종본-진짜최종.docx
fileContent:
프로젝트 F 일정 공유
2025년 10월 2일 회의
...
```

## 🧠 평가 기준

**Step1 성공 정의:**
- JSON만 출력 (no 설명, no 자연어)
- projectName 추출률 ≥ 70%
- docType 분류 정확도 ≥ 80%
- year/month 추출 ≥ 70%
- 빈 값 처리 시 `""` 사용
- 폴더 경로 규칙 유지
- newFileName 일관성

→ 이상 조건 만족 → Step2 (자동화)로 이동

## 🛠 Prompt 개선 방향

테스트 결과 기반으로 아래 규칙 추가 고려:

```
If projectName is not found in fileName,
search the first 2 lines of fileContent
for patterns like '프로젝트X', 'Project X', or code names.

For English document types:
- 'Meeting Notes' → '회의록'
- 'Invoice' → '인보이스'
- 'Contract' → '계약서'
```

이런 규칙을 Prompt에 추가하면 **정확도 상승**.
