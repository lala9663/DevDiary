# Step1: Flowise Agent 기반 분류 시스템 구축

> FlowiseAI의 Agent Flow를 기반으로 파일 정보를 분석하고,
> JSON 분류 결과를 생성하는 기능을 구현하는 단계.
> (Tool 호출 없음)

---

## 🎯 Step1 목표

- 파일 이름/내용을 입력하면 **Agent가 스스로 판단하여 분류 결과를 JSON으로 출력**
- 실제 파일 이동/태깅은 하지 않음 (정확도 검증 단계)
- Tool 사용 비활성화: **판단 능력 확보가 목적**

---

## 🧠 왜 Agent Flow인가?

Chatflow는 단순 LLM 호출 흐름이며,
Agent Flow는 **"생각 → 판단 → Tool 선택"**이라는 구조를 지원한다.

이번 Step1에서는 Tool을 끄지만,  
Step2부터 Tool을 활성화하면 다음이 가능해진다:

- Agent가 “이 파일은 이동이 필요하다” → Move Tool 실행
- Agent가 “태깅 필요하다” → Tag Tool 실행

즉, **미래 확장성을 고려하면 Step1부터 Agent Flow로 구축해야 한다.**

---

## 🧱 Flowise 구성도 (Step1)

```
[Chat Input]
      ↓
[Tool Agent (No Tools)]
      ↓
[JSON Output]
```

- Agent는 **오직 분류 판단만 수행**
- Tool 호출 없음

---

## 🛠 구성 작업

### 1. 새 Agent Flow 생성
- Flowise → Chatflows → New Flow
- 이름: `File Classification Agent (Step1)`

### 2. 필요한 노드 배치
캔버스에 아래 노드를 배치하고 연결:

```
Chat Input → Tool Agent → Text Output
```

---

## ⚙ Tool Agent 설정

Tool Agent 노드 선택 → 오른쪽 패널에서 다음 설정:

**Model**
- OpenAI GPT (gpt-4o-mini 추천)

**Tools**
- **아무것도 체크하지 않는다** (중요)

**Agent Behavior prompt (System Prompt)**  
아래 텍스트를 그대로 입력:

```
당신은 파일을 분석하여 폴더 구조와 메타데이터를 결정하는 AI 시스템입니다.
사용자가 입력한 파일 정보에서 다음 항목을 추출해 JSON 형태로 출력하세요.

필수 출력:
{
  "projectName": "",
  "year": "",
  "month": "",
  "docType": "",
  "finalFolderPath": "",
  "newFileName": "",
  "tags": [],
  "storageType": ""
}

설명:
- projectName: 프로젝트명 또는 업무명, 없으면 "".
- year/month: 날짜 추출, 모르면 "".
- docType: (회의록|계약서|견적서|인보이스|보고서|매뉴얼|기타)
- finalFolderPath: "/프로젝트명/연도/월/문서유형" 규칙 적용
- newFileName: 권장 파일명
- tags: ["프로젝트명", "문서타입"]
- storageType: public/private/confidential

규칙:
- 반드시 **JSON만** 출력하세요.
- JSON 위 아래에 다른 문장 출력하지 마세요.
- 필요한 정보가 부족하면 ""을 사용하세요.
- Tool을 사용하지 않습니다.
```

---

## 🧪 테스트 방법

Flowise Preview 화면에서 입력:

```
fileName: 프로젝트A_회의록_2025-12-01_v1.docx
fileExtension: docx
createdAt: 2025-12-01
fileContent:
프로젝트A 킥오프 회의를 진행했다. 참석자: 홍길동, 김기획.
주요 논의는 개발 일정과 역할 분담이었다.
```

### 기대 출력 예시

```json
{
  "projectName": "프로젝트A",
  "year": "2025",
  "month": "12",
  "docType": "회의록",
  "finalFolderPath": "/프로젝트A/2025/12/회의록",
  "newFileName": "프로젝트A_회의록_2025-12-01_v1.docx",
  "tags": ["프로젝트A", "회의록", "참석자:홍길동", "참석자:김기획"],
  "storageType": "public"
}
```

## 📊 Step1 완성 기준 (Done Definition)

- [ ] JSON만 출력
- [ ] projectName 판단 가능
- [ ] 연도/월 추출 가능
- [ ] docType 분류 정확도 ≥ 60~70%
- [ ] 폴더 경로 규칙 유지
- [ ] 필요 시 빈문자("") 출력 규칙 준수

위 조건을 충족하면 Step1 성공.

---

## 📝 Step1에서 관찰해야 할 것

- 어떤 문서에서 projectName 추출에 실패하나?
- 파일명 vs 본문 정보 중 무엇이 더 강한가?
- docType 추론 알고리즘을 프롬프트로 조정 가능한가?
- 태깅은 어떤 패턴으로 나오나?

이 결과를 바탕으로 Prompt를 개선하고,
Step2에서 Tool 활성화할 때 **정책으로 표준화**한다.

---

## 🔜 Step2 예고

Step2에서는 **Tool을 활성화**한다:

- MoveFile Tool
- TagRecord Tool

Agent가 생성한 JSON을 기반으로  
**n8n Webhook을 호출하거나 Google Drive API를 호출**하게 된다.

즉, Step1은 “생각하는 뇌 만들기”,  
Step2는 “그 뇌가 손발을 움직이기” 단계다.
